# 07 安全与权限设计文档

**项目名称：** Fastener AI Export Sales Agent  
**文档编号：** SEC-007  
**版本：** v0.9  
**日期：** 2026-10-30

## 1. 安全目标与威胁模型

本系统处理企业产品资料、客户联系人、询盘内容、报价和邮箱凭证。安全目标是防止租户间数据泄露、越权操作、未经授权的商业承诺、凭证泄露、恶意文件攻击和 AI 提示注入。

主要威胁：

- 用户通过修改 ID、URL 或请求体读取其他租户数据。
- 普通业务员批准自己的高风险报价或修改价格底线。
- Agent 被邮件/文档内的恶意指令诱导，执行未经授权操作。
- 客户附件包含恶意宏、脚本或异常压缩包。
- 邮箱 OAuth Token、LLM API Key、数据库凭证泄露。
- 日志、Prompt 追踪或错误监控不慎记录客户敏感内容。
- 备份文件、对象存储或私有化部署端口暴露。

## 2. 安全基线

1. 全站 HTTPS；敏感 Cookie 设置 HttpOnly、Secure、SameSite。
2. 密码使用成熟密码哈希算法（如 Argon2id/bcrypt，按依赖支持配置），禁止明文或可逆加密保存密码。
3. Access Token 短时效，Refresh Token 可撤销、轮换并检测重放。
4. 租户隔离由应用层和 PostgreSQL RLS 双重实施。
5. 最小权限原则：默认拒绝，按角色和资源授权。
6. 高风险操作执行二次服务端校验并产生审计事件。
7. 密钥进入 Secret Manager 或部署环境密钥，不写入代码仓库、镜像或普通日志。
8. 上传文件限制类型、大小和数量，隔离存储并进行恶意文件扫描。
9. AI 输出不直接触发高风险业务动作。
10. 备份加密、限制访问并定期恢复演练。

## 3. RBAC 权限模型

角色是企业内的权限集合；资源归属检查仍然必须执行。角色可在企业层扩展，但系统保留关键权限不可被任意扩大。

### 3.1 角色定义

| 角色 | 典型职责 | 高风险限制 |
|---|---|---|
| PLATFORM_ADMIN | 平台账号、租户状态、平台运维 | 默认无业务内容读取权限；支持授权临时访问并审计 |
| OWNER | 企业所有者、账单、所有企业设置 | 可管理企业管理员；不能绕过价格规则审计 |
| TENANT_ADMIN | 成员、企业配置、数据管理 | 可配置角色，但不能提升为平台权限 |
| SALES_MANAGER | 分配询盘、团队查看、报价审批（按授权） | 不能审批超过自身权限的价格例外 |
| SALES_REP | 处理分配给自己的询盘、产品查询、报价草案 | 不具备正式报价审批和价格规则修改权 |
| APPROVER | 审批报价/邮件等指定对象 | 仅能审批授权范围内对象，不能审批本人提交的高风险事项（可配置双人复核） |
| VIEWER | 查看被授权数据 | 只读，无导出敏感数据权限，除非明确授权 |

### 3.2 权限码建议

`tenant:read`、`tenant:update`、`member:read`、`member:invite`、`member:update_role`、`product:read`、`product:create`、`product:update`、`product:import`、`pricing:read`、`pricing:update`、`inquiry:read`、`inquiry:create`、`inquiry:update`、`ai:run`、`quote:create`、`quote:read`、`quote:calculate`、`quote:submit`、`quote:approve`、`quote:cancel`、`email:draft`、`email:approve`、`email:send`、`customer:read`、`customer:create`、`customer:update`、`followup:manage`、`audit:read`、`usage:read`、`data:export`。

### 3.3 权限判定顺序

1. 验证身份与令牌有效性。
2. 验证用户是否为目标租户有效成员。
3. 验证角色是否具有动作权限。
4. 验证资源的 tenant_id 与会话租户一致。
5. 验证资源状态允许当前动作。
6. 验证金额阈值、审批规则和职责分离要求。
7. 执行操作并写入审计日志。

## 4. 多租户数据隔离

- 每张租户业务表必须有 `tenant_id NOT NULL`。
- API 层从鉴权上下文获取 tenant_id，不能信任请求体或查询参数传入的 tenant_id。
- Repository 查询默认注入租户过滤；高风险表开启 RLS。
- 使用复合外键 `(tenant_id, resource_id)` 避免跨租户引用。
- Worker 从任务记录验证租户后设置事务级 RLS 上下文。
- 对象存储路径包含租户命名空间，但路径本身不是授权机制；每次下载仍需应用鉴权。
- 文件向量检索同时进行 tenant_id、文件状态和用户资源权限过滤。
- 平台运维人员不得通过通用后台直接浏览企业业务内容；支持客户授权的受控支持会话，并设置时限、原因和审计。

## 5. 审批与职责分离

MVP 所有正式报价必须由授权审批人批准。推荐策略：业务员不能批准自己提交的报价；报价金额、折扣、币种、产品、数量、贸易条款发生变化时，旧审批自动失效；价格低于底线时系统阻断，不允许普通审批人手工放行；发送邮件前再次检查报价审批状态和邮件审批状态。

邮件发送、价格表批量导入、角色升级、敏感数据导出、删除企业数据等操作均应单独授权并记录原因。

## 6. AI 安全控制

### 6.1 Prompt Injection

询盘邮件、附件、产品文档和检索片段均属于不可信输入。它们不能改变系统规则、授权边界或 Tool 权限。Agent 仅获得完成当前任务所需的只读 Tools；写入操作通过后端业务服务进行二次校验。

### 6.2 工具权限

禁止开放任意 SQL、Shell、文件系统读写、任意 URL 请求和动态代码执行。Tool 白名单、参数 Schema、超时、速率、幂等和审计均由服务端定义。模型不得决定调用者的租户身份。

### 6.3 输出校验

- 所有 JSON 结果经 Schema 校验。
- 关键产品规格需存在结构化产品数据或可信引用。
- 价格和商务承诺只能来自已授权业务数据。
- 高风险字段缺失时设置 review flag 并转人工。
- 不允许模型输出直接改变报价状态或发邮件。

## 7. 数据分类与保护

| 数据级别 | 示例 | 保护措施 |
|---|---|---|
| 公开 | 官网公开公司介绍、公开产品说明 | 按公开信息使用；仍需尊重许可 |
| 企业内部 | 产品目录、内部工艺说明 | 租户隔离、访问控制、加密存储 |
| 商业敏感 | 客户价格、折扣、成本、报价和客户名单 | 严格 RBAC、字段级/资源级权限、审计、加密 |
| 凭证秘密 | 邮箱 Token、LLM Key、数据库密码 | Secret Manager/环境密钥、轮换、严禁日志输出 |
| 个人信息 | 联系人姓名、工作邮箱、电话 | 最小必要、明确用途、保留期限、删除流程 |

## 8. 日志与审计

审计事件至少包括：登录异常、成员邀请/禁用/改角色、产品/价格规则修改、询盘导入/导出、报价创建/修改/审批/取消、邮件草案审批/发送、知识文件上传/删除、权限配置变更、敏感数据导出和管理员支持访问。

日志字段建议：event_id、tenant_id、actor_id、action、resource_type、resource_id、request_id、timestamp、result、reason、必要的 metadata。不得记录密码、Token、完整银行卡/支付数据或不必要的原始询盘正文。IP 地址可按合规要求做掩码/哈希或限制保留。

## 9. 文件与对象存储安全

- MIME、扩展名和实际文件签名交叉验证。
- 拒绝可执行文件及不支持文件类型；压缩包要限制解压深度、文件数和总大小。
- Office 宏文件默认拒绝或作为隔离风险文件处理。
- 上传后先隔离扫描，再进入解析队列。
- 对象存储 Bucket 默认私有；下载使用短时签名 URL 或 API 流式代理。
- 文件 checksum 用于去重和完整性检查。

## 10. 安全运维与合规检查

部署到中国境内或跨境提供服务时，应根据实际业务形态评估网络安全、个人信息保护、数据出境、生成式 AI 服务和企业合同要求；本文件不是法律意见。需明确模型供应商数据使用条款、数据存储地区、子处理方、删除机制和客户授权范围。企业上线前建议由法律/合规人员按实际数据流进行审查。

## 11. 安全验收

- 水平越权与跨租户访问测试 100% 阻断。
- 普通业务员无法修改价格底线、提升角色或批准高风险报价。
- 未经审批的报价和邮件发送请求均被服务端拒绝。
- 密钥扫描、依赖漏洞扫描和文件上传安全测试通过。
- 日志不出现明文密钥、Token 或不必要的客户正文。
- 备份和对象存储加密、访问控制与恢复演练通过。
