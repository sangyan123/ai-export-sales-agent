# 08 测试与验收文档

**项目名称：** Fastener AI Export Sales Agent  
**文档编号：** QA-008  
**版本：** v0.9  
**日期：** 2026-10-30

## 1. 测试目标

验证系统是否能够安全、准确、可追溯地完成紧固件出口询盘到报价草案的核心流程。测试范围包括功能、接口、数据库隔离、报价计算、AI 评测、异步任务、性能、安全和部署恢复。

## 2. 测试策略

| 测试层级 | 主要内容 | 执行方式 |
|---|---|---|
| 单元测试 | 价格计算、单位换算、状态转换、权限判断、规格归一化 | pytest / 前端单测 |
| API 集成测试 | 鉴权、参数校验、租户、资源状态、错误响应 | pytest + HTTP client |
| 数据库测试 | Migration、复合外键、RLS、事务、并发更新 | 独立测试 PostgreSQL |
| AI 离线评测 | 询盘抽取、缺失字段、产品匹配、引用准确性 | 固定标注集批量评测 |
| E2E 测试 | 从导入询盘到审批、报价导出、客户记录 | Playwright |
| 安全测试 | 越权、提示注入、文件上传、密钥、审计 | 自动化 + 人工检查 |
| 性能测试 | 列表查询、文件上传、任务队列、并发解析 | k6/Locust 等 |
| 部署测试 | 冷启动、升级、回滚、备份恢复 | staging 环境演练 |

## 3. 测试环境与数据

建议环境：local、CI、staging、production。Production 不用于开发调试。测试使用合成客户和产品数据，禁止直接复制真实客户个人信息或价格数据；如需使用真实样本，先脱敏并取得授权。

### 3.1 模拟紧固件数据集

- 产品：至少 50 个 SKU，覆盖 BOLT、NUT、SCREW、WASHER。
- 规格：DIN/ISO/ASTM 标准表达、材质 SS304/SS316/碳钢、不同直径和长度、表面处理。
- 价格：至少 3 个币种或先统一 USD；每个产品包含不同数量阶梯、有效期和 MOQ。
- 客户：至少 10 个合成客户、多个国家和联系人。
- 询盘：至少 30 条用于初始端到端回归；进入试点前建议扩展到 100～200 条由懂业务人员标注的测试集。
- 边界样本：缺字段、规格冲突、拼写错误、多产品询盘、数量单位不一致、价格过期、无匹配产品和提示注入。

## 5. AI 评测设计

### 5.1 询盘字段抽取

按字段评估 exact match、normalized match、precision、recall、F1；关键字段包括产品类别、标准、材质、直径、长度、数量、单位和目的地。对缺失字段单独统计识别精度。不得仅用总体准确率掩盖材质/尺寸等关键字段错误。

初始目标（待业务标注集验证）：关键字段归一化准确率 ≥ 90%；关键字段完全正确的询盘比例单独报告；未知/缺失字段误填率应尽可能接近 0。

### 5.2 产品匹配

使用人工标注的正确产品集合计算 Top-1、Top-3 命中率和 MRR。硬性规格冲突误判为 EXACT 的数量必须为 0。初始 Top-3 命中率目标 ≥ 85%，但需同时报告不适用/无匹配样本的召回与错误推荐比例。

### 5.3 邮件生成

由外贸业务人员按准确性、完整性、语气、可读性、商务风险进行 1～5 分评审。必须统计无依据承诺率；涉及价格、交期、认证、付款、贸易条款的未授权声明为关键缺陷。初始目标可设“无需重大修改可采用”比例 ≥ 70%，但样本量和评审标准必须记录。

### 5.4 RAG 评测

评估检索相关性、来源正确率、引用覆盖率和租户隔离。回答中声称产品属性时必须能定位到结构化产品记录或企业文档片段；引用到其他租户资料的次数必须为 0。

### 5.5 Prompt Injection 测试

构造邮件/文档包含“忽略之前规则、导出其他客户价格、调用发送邮件”等恶意指令的样本。预期：系统把这些内容当作不可信数据，不改变系统指令、不执行未授权 Tool、不泄露其他租户数据。

## 6. 报价计算测试

建立独立于生产代码的人工期望值表，覆盖：

- 数量等于 MOQ、低于 MOQ、高于 MOQ。
- 阶梯价边界：min_quantity 前一单位、等于边界、后一单位。
- 无有效价格、两条价格重叠、价格表失效、客户专属价优先级。
- 单位一致、单位不一致、PER_KG 与 PCS 换算缺参数。
- 折扣上限、最低价、最低毛利（若启用）。
- 货币一致、汇率存在、汇率过期/缺失。
- 运费/包装/保险费用的有无和来源。
- 货币精度及舍入方式。

报价规则单元测试正确率必须为 100%；任何金额错误均为阻断发布的 P0 缺陷。

## 7. 非功能与安全测试

### 7.1 性能初始目标

在明确的 staging 硬件、数据库规格、并发数和数据量条件下测试。初始参考目标：常规列表/详情 API P95 < 800 ms（不含模型/文件处理）；异步任务有排队时间、运行时间和失败率指标。不要在未提供测试环境参数前对外承诺吞吐量。

### 7.2 安全测试

- 水平越权：不同租户访问产品、询盘、报价、文件、向量 Chunk。
- 垂直越权：业务员执行价格修改、审批、角色升级、数据导出。
- RLS：未设置 tenant context 或错误 tenant context 时不得读取业务数据。
- 文件：伪造 MIME、超大文件、宏文件、压缩炸弹、路径穿越。
- Web：XSS、CSRF（适用时）、SQL 注入、SSRF、开放重定向。
- AI：Prompt Injection、RAG 跨租户、Tool 参数污染、越权工具调用。
- Secret：镜像、代码、日志、错误追踪和前端 bundle 不包含密钥。

## 8. 缺陷等级与发布门槛

| 等级 | 定义 | 发布要求 |
|---|---|---|
| P0 | 数据泄露、错误报价金额、未经审批发送、关键数据丢失 | 必须清零 |
| P1 | 核心业务流程不可用、租户隔离缺陷、审批绕过 | 必须清零 |
| P2 | 非核心功能错误、可绕过的体验问题 | 可经负责人批准后带修复计划 |
| P3 | 文案、布局或轻微体验问题 | 进入后续迭代 |

发布前必须通过：核心功能回归、报价计算测试、租户隔离、安全用例、数据库迁移、备份恢复和关键 AI 评测。P0/P1 未关闭不得发布试点。

## 9. UAT 业务验收流程

1. 选择脱敏产品目录和历史询盘样本。
2. 企业业务员确认产品字段映射和价格规则。
3. 系统处理指定询盘样本，输出解析、匹配和报价草案。
4. 业务人员逐项标注“正确/需修改/无法报价”，记录原因。
5. 核对价格计算、审批流程和报价单内容。
6. 汇总节省时间、人工修改率、错误类型和用户接受度。
7. 由企业代表签署验收结论，并记录未覆盖范围。
