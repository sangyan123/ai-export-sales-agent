# 09 部署与运维文档

**项目名称：** Fastener AI Export Sales Agent  
**文档编号：** OPS-009  
**版本：** v0.9  
**日期：** 2026-10-30

## 1. 部署目标

MVP 采用 Docker Compose 部署，支持开发、测试、SaaS 初期云端运行和小规模企业私有化。暂不引入 Kubernetes。部署包必须包含镜像版本、Compose 文件、环境变量模板、数据库 Migration、初始化脚本、健康检查、备份恢复脚本和升级说明。

## 2. 部署形态

### 2.1 SaaS 云端

平台方负责基础设施、应用、数据库、Redis 和对象存储运维；企业用户通过 HTTPS 浏览器访问。多租户共用应用服务和数据库，按 tenant_id/RLS 隔离。

### 2.2 企业私有化

企业提供符合要求的 Linux 服务器、网络、域名/证书和备份位置；交付方提供经过版本化的 Docker 镜像及 Compose 部署包。可使用企业镜像仓库、私有仓库或离线镜像包。不能要求客户自行理解每个容器并手工执行零散命令。

## 3. 逻辑容器

| 容器 | 作用 | 持久化 |
|---|---|---|
| `web` | Nginx + 前端静态文件，或独立 frontend | 可重建 |
| `api` | FastAPI 业务 API | 日志外不存业务文件 |
| `worker` | Celery 异步任务 | 任务数据在 Redis/DB，文件在对象存储 |
| `scheduler` | 定时跟进提醒、过期检查 | 配置/任务状态持久化在 DB |
| `postgres` | PostgreSQL + pgvector | 必须持久化 volume |
| `redis` | 队列和缓存 | 按配置开启 AOF/持久化；不作为唯一业务数据源 |
| `minio` | 开发/私有化 S3 兼容对象存储 | 必须持久化 volume |
| `nginx` | TLS 终止、反向代理（可与 web 合并） | 配置文件 |

生产 SaaS 可将 PostgreSQL 和对象存储托管到云服务，容器清单可相应调整。Redis 不保存唯一业务事实，数据库和对象存储是业务持久化来源。

## 4. 参考 docker-compose 结构

```yaml
services:
  api:
    image: ${REGISTRY}/fastener-ai-api:${APP_VERSION}
    env_file: .env
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_healthy }
    restart: unless-stopped

  worker:
    image: ${REGISTRY}/fastener-ai-api:${APP_VERSION}
    command: celery -A app.worker.celery_app worker --loglevel=INFO
    env_file: .env
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_healthy }
    restart: unless-stopped

  postgres:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 10

  redis:
    image: redis:7
    command: ["redis-server", "--appendonly", "yes"]
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 10

volumes:
  postgres_data:
  redis_data:
```

以上为结构示意，不可未经检查直接作为生产配置。生产环境应锁定镜像 digest/版本，配置独立网络、资源限制、非 root 用户、日志轮转、密钥挂载、TLS 和对象存储服务；数据库账号按迁移与运行用途分离。不要将真实密码提交到 `.env.example` 或 Git。

## 5. 环境配置

提供 `.env.example`，仅含键名和安全占位符。主要变量：

| 变量 | 说明 |
|---|---|
| `APP_ENV` | development/staging/production |
| `APP_SECRET_KEY` | 应用签名密钥 |
| `DATABASE_URL` | 运行账号数据库连接 |
| `MIGRATION_DATABASE_URL` | 独立 Migration 账号连接 |
| `REDIS_URL` | Redis 连接 |
| `S3_ENDPOINT` | 对象存储 endpoint |
| `S3_BUCKET` | 文件 Bucket |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | 对象存储凭证 |
| `LLM_PROVIDER` | 默认模型供应商；未设置或 `fake` 时使用本地确定性解析器 |
| `LLM_API_KEY` | 模型 API 密钥（Secret） |
| `LLM_BASE_URL` | 可选自定义服务地址 |
| `LLM_MODEL` | 解析使用的模型名称 |
| `LLM_TIMEOUT_SECONDS` | 单次模型调用超时秒数 |
| `LLM_MAX_INPUT_CHARS` | 发送给模型的询盘文本最大字符数 |
| `EMBEDDING_MODEL` | Embedding 模型及版本 |
| `JWT_ACCESS_TTL` | Access Token 有效期 |
| `LOG_LEVEL` | 日志级别 |
| `SENTRY_DSN` | 可选错误监控 DSN |

生产环境使用密钥管理服务、容器 Secret 或受限权限文件注入，不在镜像中写入 Secret。配置变更应记录操作人和时间。

## 6. 初始服务器规划

准确资源需求必须通过压测确定。作为开发/小规模试点起点，可评估：4～8 vCPU、16～32 GB RAM、SSD 200 GB 以上；数据库和对象存储增长时应独立扩容。若 Worker 同时处理大量 PDF/Embedding，应增加 Worker 资源或单独部署。生产环境必须配置容量告警和磁盘增长监控。

## 7. 发布与升级流程

1. 开发分支合并前运行静态检查、单元测试和集成测试。
2. 构建不可变镜像并生成版本号、SBOM/依赖清单（条件允许）。
3. 推送私有镜像仓库；私有化客户可获得仓库访问凭证或离线镜像包。
4. 备份数据库并确认对象存储备份/版本策略。
5. 在 staging 执行 Migration、健康检查、E2E 和回滚演练。
6. 生产先部署兼容版本，再执行向前兼容 Migration；避免一次升级同时删除旧字段。
7. 发布后检查 API 错误率、Worker 队列、数据库连接、模型调用失败率和业务关键流程。
8. 异常时按回滚预案恢复应用镜像；如 Migration 不可逆，执行数据修复/恢复方案，不得简单回滚代码掩盖数据问题。

## 8. 私有化交付包

建议每个版本交付：

```text
release-vX.Y.Z/
  docker-compose.yml
  .env.example
  images/                  # 离线交付可选
  scripts/
    install.sh
    upgrade.sh
    rollback.sh
    backup.sh
    restore.sh
    health-check.sh
  migrations/
  docs/
    INSTALL.md
    UPGRADE.md
    BACKUP_RESTORE.md
    SECURITY.md
  checksums.txt
  release-notes.md
```

客户无需逐个手动 `docker pull`。在线部署可由 `install.sh` 从授权仓库拉取锁定版本；隔离网络环境提供镜像 tar 包和校验文件，运维人员执行统一安装脚本。镜像许可证、模型授权和客户网络限制须提前确认。

## 9. 备份与恢复

### 9.1 备份对象

- PostgreSQL 数据库：每日全量逻辑备份；SaaS 生产按恢复目标增加 WAL/PITR。
- 对象存储：启用版本控制或增量/异地备份；文件与 DB 记录保持一致性。
- 配置与部署文件：纳入版本控制，但 Secret 单独安全保存。
- 邮箱和 OAuth 凭证：备份/恢复策略应遵守安全和最小保留原则，必要时要求重新授权。

### 9.2 初始策略（需按客户合同调整）

- 每日备份，至少保留 7 份日备份；每周备份保留 4 份；月度备份保留期限由合同和法规要求确定。
- 备份加密并存放于独立权限和独立存储位置。
- 定期执行恢复演练，记录恢复耗时、数据丢失窗口和失败原因。
- RPO/RTO 由 SaaS 套餐或私有化合同定义，不在没有基础设施承诺时对外保证。

## 10. 监控与告警

### 10.1 基础监控项

- API：请求量、P95/P99 延迟、5xx、认证失败、限流。
- Worker：队列长度、等待时间、任务成功/失败率、重试次数。
- 数据库：连接数、慢查询、锁等待、磁盘、复制/备份状态。
- Redis：内存、连接数、队列积压、持久化状态。
- 对象存储：容量、上传失败、访问错误。
- AI：Provider 延迟、超时、Token 用量、成本、结构化输出失败率。
- 业务：待审批报价、过期价格触发量、解析失败率、报价阻断原因。

### 10.2 告警原则

P0：跨租户数据疑似泄露、未经审批发送、金额计算异常、数据库损坏或关键数据丢失，立即通知负责人并启动事件响应。P1：API 不可用、数据库磁盘接近满、Worker 队列持续积压、模型供应商大面积失败。P2：单任务失败、文件解析异常、非关键页面错误。

## 11. 运维账号与网络安全

- PostgreSQL 不直接暴露公网；仅应用网络访问。
- Redis 不暴露公网；启用认证和网络隔离。
- MinIO 管理端仅限运维网段；S3 API 使用最小权限账号。
- SSH 使用密钥、限制来源 IP，禁止默认密码登录。
- 容器以非 root 用户运行，定期更新基础镜像和依赖。
- 数据库迁移账号与业务运行账号分离。
- 管理员操作使用 MFA（可用时）和审计记录。

## 12. 故障处理手册

| 故障 | 检查方向 | 处理建议 |
|---|---|---|
| API 无法启动 | 环境变量、数据库连接、Migration、镜像版本 | 查看启动日志，修复配置后重启 |
| Worker 无任务处理 | Redis、队列名、Worker 心跳、任务错误 | 检查队列积压，重启前先确认任务幂等 |
| 文件解析卡住 | 对象存储、文件类型、扫描服务、Worker 资源 | 标记失败并重试；保留原始文件 |
| AI 请求失败 | Provider 状态、Key、额度、超时和限流 | 降级/切换 Provider，任务退避重试 |
| 数据库磁盘告警 | 表膨胀、日志、备份和附件策略 | 扩容并执行归档/清理，先确认备份 |
| 报价数据不一致 | 价格版本、并发更新、快照、舍入 | 暂停相关报价，保留证据并修复数据 |

## 13. 运维验收

- 新环境可按照交付包完成安装，健康检查通过。
- 数据库 Migration 能从空库完整执行。
- 备份可在隔离环境恢复，应用可读取恢复后的业务数据和文件。
- 升级、回滚和密钥轮换流程有可执行说明。
- 监控覆盖 API、数据库、Worker、Redis、对象存储和模型调用。
- 客户无需手工管理每个容器；在线和离线镜像交付方式均有说明。
