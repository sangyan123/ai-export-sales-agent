# 01 产品需求文档（PRD）

**项目名称：** Fastener AI Export Sales Agent（工业紧固件 AI 外贸业务员）  
**文档编号：** PRD-001  
**版本：** v0.9（首版基线草案）  
**日期：** 2026-10-30  
**状态：** 待业务访谈验证 / 可用于 MVP 工程拆解

> 本文档用于统一首版产品范围。行业选择、用户画像、自动化边界和指标均为当前产品假设；在获得真实紧固件出口工厂反馈后，应形成 v1.0 基线。不得将模拟数据测试结果描述为真实客户验证结果。

## 1. 产品概述

### 1.1 产品定位

面向中国中小型工业紧固件出口制造企业，提供询盘解析、产品匹配、规则化报价、商务邮件生成和客户跟进记录的一体化 AI 业务员助手。首批支持标准及轻定制的螺栓、螺母、螺钉、垫圈等产品类型。

产品不是通用聊天机器人，也不是全自动外贸经营系统。核心承诺是：将客户询盘转换为可追溯的结构化需求，依据企业授权的产品与价格数据生成报价草案和回复邮件，并由企业人员审批后执行。

### 1.2 产品目标

1. 缩短业务员从收到询盘到形成首份有效回复草案的时间。
2. 降低重复复制产品规格、查目录、查价格和编写英文邮件的工作量。
3. 减少因规格遗漏、错误匹配、过期价格或无审批报价造成的风险。
4. 将询盘、客户、产品、报价、邮件与跟进记录沉淀为可追溯业务数据。
5. 形成可跨企业复用的 SaaS 核心能力，同时允许企业级配置和集成。

### 1.3 非目标

MVP 不承诺自动寻找全球采购商、不抓取或绕过 B2B 平台、不自动批量发送开发信、不进行自主谈判、不自动签订合同、不执行收款/订单履约、不替代工程师审核非标图纸，也不保证 AI 生成内容可不经检查直接对外发送。

## 2. 目标用户与场景

### 2.1 目标企业画像（待验证）

| 维度 | 首选画像 | 暂不优先 |
|---|---|---|
| 企业类型 | 中国中小型紧固件制造/出口工厂 | 纯贸易撮合平台、大型跨国集团 |
| 产品 | 螺栓、螺母、螺钉、垫圈及相关标准件 | 高安全等级航空/汽车专用件 |
| 业务模式 | B2B 批量询价、重复产品及轻定制 | 完全依赖工程设计的复杂项目 |
| 数据基础 | 有产品 Excel、PDF 目录、价格表 | 产品资料完全缺失且无维护负责人 |
| 业务流程 | 邮件/平台询盘由业务员人工处理 | 已有高度自动化报价系统且不计划替换 |
| 典型诉求 | 快速识别规格、查产品、报价、回复和跟进 | 仅需要一次性翻译或单纯客户名单 |

### 2.2 用户角色

- **企业所有者 / 租户管理员（OWNER / TENANT_ADMIN）：** 企业配置、成员管理、业务规则和数据权限。
- **外贸主管（SALES_MANAGER）：** 分配询盘、审核报价、查看团队业务数据。
- **外贸业务员（SALES_REP）：** 录入询盘、查看匹配、准备报价和邮件、维护客户。
- **报价审批人（APPROVER）：** 审核价格、折扣、付款及交付条款。
- **只读用户（VIEWER）：** 查看被授权的业务信息。
- **平台运维管理员（PLATFORM_ADMIN）：** 维护 SaaS 平台，不默认拥有企业业务内容读取权限；必要访问须经授权并留痕。

### 2.3 核心用户故事

1. 作为业务员，我可以粘贴客户邮件或上传 EML/PDF/Excel，使系统建立一条询盘记录。
2. 作为业务员，我可以查看 AI 提取的产品、标准、材质、直径、长度、数量、目的地及缺失字段，并修正错误。
3. 作为业务员，我可以看到候选产品、匹配理由、冲突字段和资料出处，而不是只看到一个无法解释的匹配分数。
4. 作为业务员，我可以基于有效产品和价格规则生成报价草案，并查看报价使用的数据版本。
5. 作为审批人，我可以批准、驳回或要求修改报价，并查看价格底线、折扣和风险提示。
6. 作为业务员，我可以基于询盘和已批准报价生成客户回复邮件；发送前必须通过审批状态检查。
7. 作为主管，我可以查看询盘处理状态、待审批报价、待跟进任务和操作记录。

## 3. 产品范围与版本规划

### 3.1 MVP 范围（P0）

| 模块 | 必须交付的能力 | 不纳入 MVP 的能力 |
|---|---|---|
| 账户与企业 | 注册/登录、企业空间、成员邀请、基础角色 | SSO、复杂组织树 |
| 企业资料 | 公司信息、主营产品、出口市场、默认币种和语言 | 多法人合并管理 |
| 产品中心 | 产品 CRUD、Excel 模板导入、规格字段、启停用 | ERP 实时同步、复杂 BOM |
| 知识资料 | PDF/DOCX/XLSX 上传、解析状态、资料来源 | OCR 处理所有扫描件、CAD 图纸解析 |
| 询盘中心 | 文本录入、EML/附件导入、状态管理 | 多平台自动抓取 |
| AI 解析 | 结构化字段提取、置信度、缺失项识别 | 自主对外追问发送 |
| 产品匹配 | 精确过滤 + 候选排序 + 匹配解释 | 自动替代不兼容规格 |
| 报价中心 | 价格表、阶梯价格、报价快照、报价草案 | 自动核算复杂海运/关税/税务 |
| 邮件助手 | 多语言邮件草案、编辑、复制/下载 | 无审批自动发送 |
| 客户管理 | 客户档案、联系人、询盘关联、历史记录 | 外部客户数据采集 |
| 跟进管理 | 手动/规则生成待办、到期提醒 | AI 自主谈判和无限期自动追踪 |
| 审计与用量 | 关键操作日志、AI 调用记录与用量统计 | 企业 BI 数据仓库 |

### 3.2 后续版本

- **P1：** IMAP/SMTP 邮箱接入、Gmail/Microsoft Graph 接入、客户分配、团队审批流程、跟进自动化、更多产品类别模板。
- **P2：** ERP/CRM 适配器、B2B 平台官方 API 接入、客户信息辅助研究、销售分析、私有模型部署选项。
- **P3：** 订单协同、生产/物流状态整合、复杂定制件工作流、多 Agent 协作。

## 4. 核心业务流程

### 4.1 询盘处理主流程

```text
手动录入/导入询盘
  -> 保存原文和附件
  -> 创建解析任务
  -> LLM 提取结构化需求
  -> Schema 校验与字段归一化
  -> 展示缺失字段/冲突字段
  -> 业务员确认需求
  -> 产品精确过滤与候选排序
  -> 查询有效价格规则
  -> 确定性报价计算
  -> 生成报价草案与回复邮件
  -> 人工审核/审批
  -> 导出报价/人工发送邮件
  -> 写入客户历史与跟进任务
```

### 4.2 关键业务原则

- 原始询盘不可被解析结果覆盖；必须保留原文、来源、导入人和导入时间。
- AI 未识别的字段使用 `null` 或 `unknown`，禁止自行补造。
- 关键规格缺失或冲突时，系统应提示补充信息，不得自动认定产品完全匹配。
- 报价计算由后端规则引擎完成，LLM 不负责最终金额计算。
- 正式报价必须由授权人员审批；报价审批通过后才可生成可发送状态。
- 所有报价保存价格、汇率、运费、规则和产品数据快照，历史报价不能随当前产品价格变动而改变。

## 5. 功能需求与验收标准

### 5.1 询盘管理

- 支持纯文本粘贴；支持 `.eml`、`.pdf`、`.docx`、`.xlsx` 文件导入。
- 单次上传文件大小、数量限制由系统配置；MVP 默认建议单文件不超过 20 MB。
- 同一租户内可按客户、状态、日期、产品关键词查询。
- 询盘状态统一使用：`RECEIVED`、`PARSING`、`NEEDS_INFO`、`READY_FOR_MATCH`、`MATCHED`、`QUOTE_DRAFTED`、`PENDING_APPROVAL`、`QUOTE_APPROVED`、`REPLIED`、`WON`、`LOST`、`ARCHIVED`。
- 解析失败时保留询盘，允许重试或人工录入，不得丢失原始内容。

### 5.2 产品管理

- 产品编码在同一租户内唯一。
- 支持产品类别、标准、材质、等级、直径、长度、螺距、头型、驱动类型、表面处理、计价单位、MOQ、包装信息等字段。
- 允许企业扩展自定义属性，但核心匹配字段必须结构化。
- Excel 导入提供模板、字段映射、预览、错误行下载和失败回滚能力。

### 5.3 产品匹配

- 先执行硬性约束过滤，再对剩余候选项排序。
- 企业设置为必需的规格字段如材质/标准/尺寸发生冲突时，不得判定为“完全匹配”。
- 每个候选项提供命中字段、冲突字段、未知字段和数据来源。
- 初始评分阈值属于待校准参数，不能作为行业准确率承诺。

### 5.4 报价生成

- 支持按件、按公斤、按套和按批次等计价单位；具体企业可启用的单位需配置。
- 支持阶梯价、MOQ、币种、有效期、客户专属价及价格底线。
- 报价不可用、过期、缺少价格、低于底线或产品规格不匹配时，应阻止正式报价。
- 报价金额采用 Decimal 运算；金额精度和舍入规则按币种及企业设置执行。
- 报价单包含产品、规格、数量、单价、金额、币种、贸易条款、交期、付款条件、有效期和备注；未确认信息不得编造。

### 5.5 邮件生成与发送

- 邮件正文必须基于原始询盘、已确认需求、产品数据和已批准报价。
- 生成内容显示数据来源和需人工确认项。
- MVP 提供复制/下载，不默认接入真实邮箱发送。
- 后续接入发送时，后端必须验证报价状态、邮件审批状态、收件人、发件账号授权和幂等键。

## 6. 产品页面与导航

1. 工作台：待处理询盘、待审批报价、待跟进任务和最近活动。
2. 询盘管理：列表、详情、原始邮件、AI 解析、匹配候选和处理记录。
3. 产品中心：产品列表、规格详情、价格表、资料文件。
4. 报价中心：报价草案、审批队列、报价历史和导出。
5. 客户管理：客户、联系人、询盘时间线和备注。
6. 跟进管理：任务列表、到期时间、负责人和完成记录。
7. AI 工作台：任务运行状态、失败原因、模型用量和评测状态。
8. 企业设置：成员角色、企业资料、价格规则、邮箱配置、模型配置和数据管理。

## 7. 非功能需求

| 类别 | MVP 要求 |
|---|---|
| 性能 | 常规列表/详情 API 在目标部署环境下 P95 目标小于 800 ms（不含模型/文件处理） |
| 异步任务 | 文件解析、Embedding、LLM 调用均可异步执行；支持重试、超时和失败记录 |
| 可用性 | 核心 API、数据库、Worker 配置健康检查；部署具备基本恢复流程 |
| 安全 | HTTPS、密码哈希、租户隔离、RBAC、敏感配置不入库明文、审计日志 |
| 可追溯性 | 询盘、匹配、报价、审批、邮件草案可串联查询 |
| 可维护性 | 模块化单体、数据库迁移、自动化测试、结构化日志 |
| 可扩展性 | LLM Provider、邮件 Provider、对象存储使用适配层 |
| 国际化 | MVP 中文管理界面，支持生成英文邮件；界面多语言后续扩展 |

## 8. MVP 成功指标（初始目标）

以下仅为研发阶段的验收目标，须使用固定标注测试集验证，不代表商业承诺：

- 关键询盘字段归一化准确率目标 ≥ 90%。
- 产品匹配 Top-3 命中率目标 ≥ 85%，且必需规格冲突不得被标记为完全匹配。
- 报价计算规则测试用例正确率 100%。
- 未经审批的正式发送次数为 0。
- 跨租户访问测试全部阻断。
- 每次报价均能追溯价格表、价格规则、产品快照和审批人。
- 至少完成 30 条模拟询盘的端到端回归；进入试点前扩充至经业务人员标注的测试集。

## 9. 关键假设与待验证问题

1. 目标工厂是否愿意提供脱敏产品目录和价格样本用于试点？
2. 询盘是否以邮件为主要入口，还是阿里巴巴国际站等平台消息占比更高？
3. 报价常见基准是按件、按公斤还是按重量/批次？
4. 不同客户是否有专属价、折扣权限和最低毛利约束？
5. 业务员是否愿意使用独立工作台，还是必须与现有邮箱/CRM 集成？
6. 企业对云端模型处理客户询盘和产品资料的接受程度如何？

## 10. 交付定义

MVP 只有在以下条件全部满足后才可标记为“可试点”：可创建企业和用户、导入产品、上传资料、导入询盘、完成 AI 解析和产品匹配、按真实配置规则计算报价、生成邮件草案、执行人工审批、导出报价、保留全链路记录，并通过租户隔离与核心回归测试。
